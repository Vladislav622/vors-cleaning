# Ворс — веб-приложение для выездной химчистки мягкой мебели

Переиспользуемый шаблон MVP: клиент выбирает мебель на 3D-модели, видит предварительную цену и отправляет заявку; владелец в кабинете видит состав и фото, согласует цену и время, клиент видит изменения по приватной ссылке.

Название «Ворс», компания и все демо-данные вымышленные.

## Запуск локально

Нужны Node.js 20.9+ и PostgreSQL 14+.

```bash
npm install
cp .env.example .env.local          # заполните DATABASE_URL, ADMIN_PASSWORD (≥10 символов), APP_URL
set -a; . ./.env.local; set +a       # Windows PowerShell: задайте переменные вручную
npm run db:migrate                   # создаёт таблицы (можно запускать повторно)
npm run db:seed                      # стартовые настройки; npm run db:seed -- --demo — вымышленные заявки
npm run dev                          # http://localhost:3000, кабинет — /admin
```

Продакшн: `npm run build && npm start`.

## Публикация (Vercel + Neon — пример)

1. Создайте базу PostgreSQL (Neon, Supabase или свой сервер) и возьмите строку подключения с `sslmode=require`.
2. Выполните `npm run db:migrate` и `npm run db:seed` с этой строкой.
3. Импортируйте репозиторий в Vercel, задайте переменные окружения `DATABASE_URL`, `ADMIN_PASSWORD`, `APP_URL` (адрес сайта), при необходимости `APP_TZ` (по умолчанию `Asia/Almaty`).
4. Задеплойте, войдите в `/admin` паролем из `ADMIN_PASSWORD` и сразу смените его в разделе «Доступ».

Заявки и фото хранятся в PostgreSQL, а не в файлах — это работает в serverless. Секреты используются только на сервере.

**Что не сделано в рамках этой передачи:** сайт не опубликован — для этого нужен ваш аккаунт Vercel (или другого хостинга) и база данных; доступов к ним у меня не было. Шаги выше занимают ~15 минут.

## Правила расчёта

```
цена за штуку = округлить_вверх( база_варианта × (1 + %второй стороны, только матрас) × (1 + %сильных загрязнений), шаг )
строка = цена за штуку × количество
чистка = сумма известных строк; если меньше минимального заказа — доплата до минимума
итого = чистка + фиксированный выезд за город (не входит в минимум)
```

- «Другое» не имеет цены: показывается «по фото», никогда не 0. В смешанном заказе показывается «от N + по фото».
- Если в заказе только «Другое», минимум не навязывается — цену называет мастер.
- Сервер заново валидирует состав и считает сумму; суммы из браузера не принимаются.
- В заявке сохраняется снимок прайса и расчёта — изменение тарифов не меняет старые заявки.

## Безопасность

- Кабинет: пароль (scrypt), сессия в httpOnly-cookie `SameSite=Strict`, хеш токена в БД. Смена пароля закрывает все прежние сеансы.
- Изменяющие запросы проверяют `Origin` / `Sec-Fetch-Site`. Лимиты запросов хранятся в PostgreSQL (работают в serverless).
- Ссылка на заявку — случайный токен (24 байта); по номеру заявки её открыть нельзя. Публичный API не отдаёт телефон, приватную заметку и фото.
- Фото: проверка сигнатуры и декодирование, удаление EXIF (в т. ч. геометок), пережатие в WebP ≤1600 px, хранение в БД. Отдаются только через сессию владельца, публичного адреса нет. Неприкреплённые загрузки удаляются через сутки.
- Повтор отправки с тем же ключом идемпотентности возвращает ту же заявку (уникальный индекс + сравнение хеша содержимого).

```bash
npm run typecheck

python3 tests/e2e/flow.py  http://localhost:3000 <пароль> ./qa     # сквозной сценарий, нужен Playwright + Chrome
```

Результаты прогона 13.11.2026 на локальном продакшн-сборке (Chrome headless, SwiftShader, ширина 390 px и 1280–1366 px): типы и сборка — ок; 6/6 юнит-тестов; 37/37 проверок сквозного сценария; 10/10 доп. проверок. **На реальном телефоне не проверялось** — физического устройства в сессии не было.

## Ограничения MVP

- Нет онлайн-оплаты, расписания мастеров, ролей, CRM и уведомлений (SMS, Telegram, email) — владелец смотрит заявки в кабинете сам.
- Один владелец, один пароль. Одна компания — один экземпляр и одна база.
- Бонус из игры выдаётся по сигналу браузера: это не античит. Погашение — вручную, кнопкой в карточке заявки.
- Фото хранятся в PostgreSQL (≤3 на заявку, ~150–400 КБ каждое). При большом потоке стоит вынести в объектное хранилище.
- 3D-модели процедурные и стилизованные: показывают тип и вариант (2/3 места, угловой, реклайнер, ширина матраса, мягкая спинка стула), но не точные размеры и ткань — это сказано пользователю над сценой.
- Время согласованного выезда показывается клиенту в часовом поясе `APP_TZ`.
- Политика обработки данных — шаблон, её нужно проверить с юристом.
- Модели из библиотеки Innerscene (CC0) не использованы: сайт закрыт проверкой Cloudflare, проходить её автоматически нельзя. Все модели созданы с нуля скриптом в Blender — лицензионных ограничений нет.
